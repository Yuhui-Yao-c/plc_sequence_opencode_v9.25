解析示例

① 原始 XML 结构（关键字段）PLCopen LD
<inVariable localId="1">
  <expression>Cell.Phase[4]</expression>
</inVariable>
<inVariable localId="2">
  <expression>500</expression>
</inVariable>
<block localId="3" typeName="EQ">
  <connection refLocalId="1"/>
  <connection refLocalId="2"/>
</block>
<contact localId="4">
  <connection refLocalId="3"/>
  <variable>Axis.Arrived</variable>
</contact>
<block localId="6" typeName="MOVE">
  <input formalParameter="EN">
    <connection refLocalId="4"/>
  </input>

<outVariable localId="7">

→ Cell.Phase[4] := 530

05 / EVIDENCE MODEL

候选不是结论：系统按证据强度逐级提高可信度

证据模型

不同来源可以共同描述一段逻辑，但“观察到”“连接到”“控制了写入”是不同强度的事实。

LEVEL 01
状态值观察

从比较、赋值和 MOVE 目标中发现状态变量和值，形成高召回候选。

recall_candidates.csv
LEVEL 02
同域事件观察

同一网络或程序单元出现命令、反馈、状态目标；共现不等于因果。

event_graph.csv
LEVEL 03
显式连线追踪

从 EQ 状态锚点沿连接追踪到 MOVE.EN 或动作节点。

control_relations / action_trace
LEVEL 04
局部迁移证据

恢复门控、写入目标、作用域及阻断项，得到可解释的迁移关系。

source_transition_graph.json
LEVEL 05
专项协议证据

跨 FB 触发—接收、InlineST 副作用与信号收尾等专门关系。

cross_fb / signal lineage

证据链回答什么？

某条候选从哪个控制器、哪个 POU、哪个网络或节点发现；由哪些比较、触点、写入和反馈支撑。

证据链不能自动回答什么？

不能仅凭同域共现证明因果；不能凭 Done / Arrived 变量名证明物理完成；不能凭步号相邻证明程序迁移。

工程红线：未知函数、动态写入、分支旁路、作用域歧义和不完整路径必须保留为 blocker 或待核验信息，不应静默删掉。
主要模块：recall.py · event_graph_v6.py · successor_graph.py · fb_transport.py06 / 15
06 / CANDIDATES & BOUNDARIES

候选与边界

边界处理不是“把状态号排一遍”，而是依据源码迁移图和门控证据，转换候选的表达形式与采集粒度。

候选生成与筛选顺序
全量源码解析状态观察 / 事件 / 迁移图
→
完整候选池候选 ID / 控制器 / 来源
→
变量范围筛选可选 --pattern
→
边界规范化迁移证据约束
→
采集视图原子对 / 收尾合并

candidate_filter.py 使用符号识别、glob 或 re: 正则匹配开始/结束标签；process_focus_queue 是审查优先队列，不替代主候选池。

A / FIRST EXIT

状态集合首出口

沿有来源的迁移边搜索第一次离开指定状态集合的出口，不按步号大小推断。

100 → 135
100 → NOT(100)
规范为 100 → 135
B / ATOMIC

复合边界原子化

可证明的 OR 分支拆成独立原子对；AND 门控不能为了简洁而直接删除。

(S=100 OR S=200)
→ 两条独立分支
C / FEEDBACK

反馈条件后继

当反馈是直接迁移必要条件时，可将反馈条件边界映射到状态后继；不宣称布尔等价。

S=70 AND F
MOVE: S:=4
候选：70 → 4
D / SIGNAL TAIL

动作与信号收尾合并

若后段只是动作的信号/数据收尾且没有新动作，可在采集视图合并。

原始：A→B，B→C
采集：A→C
保留原始段与 lineage
时间口径：收尾合并会把 B 阶段内部延时纳入 A→C 的计时跨度；它不是原图新增一条直接迁移边。OR 分支分别计时，AND 条件保留。
主要模块：boundary_normalizer.py · atomic_boundaries.py · feedback_successor.py · signal_tail_merge.py07 / 15

09 / FINISH & VALIDATION

finish 不只是汇总：它负责验证 Agent 结果能否被源码证据支撑

结果校验

每个批次都必须满足可追溯协议。没有来源的步骤、越批引用、标签不匹配或遗漏事件都会形成校验问题。

逐批校验
1
批次身份正确

result.json 中的 batch_id 必须与输入批次一致。

2
证据 ID 合法

候选 ID / 事件 ID 必须存在，且属于当前批次，不能越批引用。

3
起止标签可核验

开始标签、结束标签必须能由引用候选对应核验。

4
事件完整覆盖

每个事件必须进入 steps 的证据引用，或进入 unresolved_events。
