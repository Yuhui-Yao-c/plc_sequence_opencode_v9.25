怎么提取状态迁移 MOVE 块的 EN 引脚回溯

MOVE 块结构

         ┌─────────┐
  EN ────►│  MOVE   │
          │         │
   110 ──►│IN   OUT│──► ST01.AutoStep[2]
          └─────────┘

# EN=TRUE 时，把 IN(110) 赋给 OUT
# 要提取的迁移：在什么条件下
# 状态从当前值变成 110

EN 的值藏在前面连的逻辑里，要沿连线回溯求值

EN 回溯求值

 S=100 ──EQ──┐    ┌──┐
               └──┤AND├──EN──┐
 Clamping ───────┘   └──┘   │
                          ┌──┴────┐
                    EN ───┤ MOVE  │
                    110 ─►│IN  OUT│──► S
                          └───────┘

# 回溯得到完整 guard：
# (S=100) AND Clamping

于是输出迁移：from=100, to=110, guard=(S=100) AND Clamping

回溯过程（三种格式各自的电源流求值器）

格式求值器连线模型遇到什么
PLCopenWireBodylocalId/refLocalIdLeftPowerRail→TRUE · contact→AND(var) · EQ块→AND(pred) · AND/OR/NOT→组合
SMC2GridCLs横+VLs纵 并查集多输入→OR组合 · IST节点→STParser
omronNativeRungconnectionPointOutId 按Rung作用域symbolic_gate降级 · InlineST外部guard作前提 · TON.Q保留时序
遇到这些就阻断（进 blockers 不丢）：未知FB输出 · 边沿指令 · 数据输入非单一来源 · 上游MOVE写了被依赖变量 · guard超预算

ST 代码怎么解析 双轨 strict · 两类 ST 出现位置语义不同

strict=True · InlineST 尾段

# Rung 内嵌的 ST 尾段
IF S=100 AND Clamping THEN
  S := 110;        # ← 可证
  strInfo := '取料';  # ← 字符串，阻断
  CallFB();        # ← 调用，阻断
END_IF;

不可证语句整段阻断（抛 WireError）

守护"动作+信号收尾合并"的零副作用前提

strict=False · omron 大状态机

# BodyContent 下的 ST body
CASE iCmdStep OF
100: AutoStep[2]:=210;  # ← 可证
     strStepInfo:='Z轴下降'; # skipped
210: AutoStep[2]:=220;  # ← 可证
END_CASE;

不可证语句降级为 skipped 记录，body 其余可证写保留

大状态机里 strStepInfo/调用太多，全阻断会导致 0 候选

效果（配对机工程）：ST bodies 65→333 · transitions 2→1944 · 完整候选 0→1155
RETURN 仍阻断（其后不可达）；skipped 计数进 native_parse_audit，明细在 native_inline_slices.json

候选池怎么攒起来 三种格式，同一个原理：找到"谁触发了状态赋值"

PLCopen 梯形图：MOVE 块的 EN 引脚回溯

EN 有信号时 MOVE 才执行；回溯 EN 找到 EQ 比较块 = 当前状态

① PLCopen MOVE 块

梯形图 MOVE 块的 EN 引脚回溯到 EQ 比较块
→ S=110 触发 + S=120 赋值

② omron ST CASE 分支

CASE nStep OF 110: ... nStep:=120;
→ 分支号 = 当前状态，赋值 = 目标状态

③ SMC2 Rung 路径

类似 PLCopen，按 Rung 作用域回溯路径
→ 找到使能条件 + 赋值目标

核心原理：三种格式回答同一个问题 —— "谁触发了状态赋值"
触发条件（开始）+ 赋值目标（结束）= 一条候选迁移
跨 FB 触发、信号收尾合并等是后续补充来源，不删原始行

复合标签怎么变单状态等式 边界规范化 + 原子投影

规范化前（候选池里）

开始: S=100
结束: NOT(S=100 OR S=120)

开始: (S=100 OR S=200)
结束: NOT(S=100 OR S=200)

开始: S=100 AND Ready
结束: S=110

开始: S=100 AND Arrived
结束: S=110

含 OR/AND/NOT 复合式，进不了交付表

规范化后（主表）

开始: S=100
结束: S=135     # 区域首出口BFS

开始: S=100      # OR分行
结束: S=135
开始: S=200
结束: S=245

# AND 不删 → 待核验
开始: S=100 AND Ready
结束: S=110

# 反馈 → 直接后继
开始: S=100
结束: S=110     # 条件替代

单状态等式或单 BOOL

区域首出口 BFS（核心算法）

# 输入: S=100 → NOT(S=100 OR S=120)
# 源图: 100 → 120 → 135 → 180
从 100 出发沿源码迁移 BFS：
  120 在集合内 → 继续
  135 首次离开集合 → 取 135
# 不跨过出口找 180

规则：OR 分支分行（不做笛卡尔积）· AND 条件不删 · 不按数值最近猜 · 不跳远端汇合点 · 反馈后继沿源码必需直接迁移投影

动作+信号收尾怎么合并 signal_tail_merge · 输出新的计时区间

动作 A→B
有 motion_command
紧接
信号/数据处理 B→C
无新动作
合并
采集区间 A→C
内部延时计入

尾段需满足的条件（全满足才合并）

  • 单一无条件字面状态赋值
  • 单一前驱、单一出口
  • 有正向信号/数据 effect
  • 无新动作（motion_command 启发式）
  • 无跨控制器写
  • 无 unsafe 字段（Execute/Enable/Start/...）
  • 无 skipped_st_call_may_write_state
  • 无环路、无独立等待

产物分层

prediction_atomic_pairs.csv
  EM01.Step=10 → EM01.Step=20
  EM01.Step=20 → EM01.Step=30
  EM01.Step=30 → EM01.Step=50

  EM01.Step=10 → EM01.Step=50
  合并路径: 10→20→30→50
  合并ID: M3f2a...

原始分段始终保留在 atomic 文件

合并是新的计时区间，不是边界等价。任一条件不满足进 review，不盲合并。

动作描述怎么生成 A 档源码步注释 + B 档 LLM 补充

源码 ST 里的步注释

abEM08ActionStart[3] := ST01.AutoStep[2]=210;
                                //Z轴下降到取料位
abEM08ActionStart[4] := ST01.AutoStep[2]=220;
                                //电夹爪放料

extract_step_comments 提取为 step_comments.json：

{
  "ST01.AutoStep[2]=210": "Z轴下降到取料位",
  "ST01.AutoStep[2]=220": "电夹爪放料"
}

人工表 97.7% 描述逐字来自这些注释

A 档优先级（cmd_a）

  1. step_comments.json[start_label] → 纯中文步注释
  2. CSV 动作描述列（codesys 步注释，过滤模板）
  3. 留空 → 交 B 档
变量翻译不进描述列（含英文），只进"动作变量引用"列

B 档 LLM 补充

A 档为空的行 → cmd_build 生成批次 → agent 写 result → cmd_validate 合并 B+A

v9.25：注入变量文档 + step_comment 上下文 + "一行一动作重点"

B 档白名单①

refs⊆tokens：引用变量必须在该行动作变量内

白名单②

无英文标识符：≥2字符 ASCII 标识符则拒

白名单③

中文词命中白名单：verbs+members+通用机构词

  • 构成要素 ← station_identity + SC04 后缀

  • 动作变量 ← plcopen_action_trace 等

  • 备注 ← network_comments.json + 待复核标记

样式

  • 工位列纵向合并，块尾"总时长"行
  • 统一 Arial 9，行高 18
  • 待复核：备注列红色加粗【待复核】
  • 排序：EM/ST 数值序（EM01<...<EM10）
  • 排序仅为展示，不代表执行顺序
